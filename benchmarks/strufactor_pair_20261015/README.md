# Stru_factor pair 布局实验

日期：2026-10-15。GPU：RTX 4080 SUPER，CUDA 12.6，`nvcc -O3 -std=c++17 -arch=sm_89`。

## 范围与实现

实验文件全部位于本目录，构建产物位于 `build/strufactor-pair`。
实验开始及结束核对 `src`、`include`、`cmake` 和根 CMakeLists 的 SHA-256，生产文件保持原样。
`benchmark.cu` 通过 `ZQC_STRUFACTOR_KERNELS_ONLY` 包含生产 `CVs_Strufactor.cu`，
从而直接使用现有中心 kernel 和相同的 `radial()`，避免重复维护数学公式。

对比三种反向布局，前向均调用现有中心 kernel：

- `center`：一个线程处理中心的全部邻居，先在寄存器中累加中心贡献。
- `directed_pair`：一个线程处理一个有向邻居槽位；检查有效邻居数后对两个端点原子累加。
- `half_pair`：有互逆边时只处理一次，径向导数乘两个中心 adjoint 之和；单向边使用原中心 adjoint。

half-pair 中可合并的两个中心拥有相同的 q 和 cutoff。该实验从当前有效邻居生成配对表，
支持部分中心组及单向边；尚未实现生产环境中配对表的更新和 MPI 接入。

## 正确性

- 非连续中心编号、组外邻居、没有邻居的中心、空中心组、正负及零种子。
- 每中心段尾保留空槽，邻居写入非法编号、几何写入 NaN，检查有效边界。
- 输出尾部哨兵、可选 virial 指针，以及小距离的解析极限。
- 逐原子原始值对照独立 CPU 公式，力和逐原子六分量 virial 对照生产 kernel。
- 24 个坐标分量和 6 个应变分量做独立能量的中心有限差分。

12 个性能场景全部通过数值对照。最大力差约 1.69e-14，逐原子 virial 差约 2.22e-14；
有限差分的最大力误差 3.18e-10、virial 误差 2.30e-10，最大总净力约 2.60e-13。

## 计时方法

使用有微小扰动的周期 FCC，5324/16384 个原子，每中心 12/42/140 个邻居；
分别使用全部原子和均匀分布的 64 个原子作为中心，保留每中心 4–8 个无效尾部槽位。
64 中心用于观察并行度不足的情况，不能代表所有小原子组的空间分布。

每种方案预热后进行 9 轮随机顺序计时，取中位数，原始 CSV 同时保存最小值与最大值。
CUDA event 测量每次含 32 步的 CUDA Graph 重放，每轮约 30 ms；该 CUDA Graph 仅用于批量提交计时，
与项目的表达式 Graph 不同。全部方案都计入力和 virial 清零，以及完整的力/virial 累加。
前向+反向阶段使用同一组固定且非均匀的 adjoint，Graph 中的种子计算不在计时范围内。

计时范围为固定几何上的 GPU kernel，排除了环境更新、pair 表准备/上传、MPI、D2H、
表达式 Graph 和完整 LAMMPS timestep。桌面 GPU 未锁频，各轮有波动，几个百分点的差异应谨慎解释。

## 配对准备成本

有向 pair 需要槽位到中心的映射，可在候选邻居布局改变时重建；本测试从 Host 上传一次。
half-pair 为验证公式使用 Host 哈希表寻找互逆边，准备耗时单独列在 CSV 中。
全中心场景准备约 1.65–170.85 ms，远大于单步 kernel 的节省，且这里还未计入映射上传。
例如 16384 中心、42 邻居，Host 建表约 41.1 ms，而本轮前向+反向只节省约 0.029 ms。
因此当前 half-pair 原型不能直接按每步 Host 建表的方式接入生产。
生产化需要解决表的复用、邻居重排后的失效、有效边更新，以及 owned/ghost 的贡献归属。

优先考虑小中心组的有向 pair；大中心组保留中心版本作为基准。
half-pair 可继续验证高效建表/复用方案，随后再测完整 LAMMPS 流程。

## 复现

```bash
python benchmarks/strufactor_pair_20261015/run.py --rounds 9
```

可通过 `NVCC`、`LAMMPS_SOURCE_DIR`、`MPI_HOME` 覆盖工具路径。
编译目标为当前设备的 sm_89；在其它 GPU 上运行需要调整 `run.py` 的架构参数。
输出包括 `build.log`、`run.log`、`results.csv`、含源码校验值和编译命令的 `results.json`。
本目录的 `results.csv`、`results.json` 与 `validation.log` 保存本次测量快照。
